# 安全知识库使用说明（主链模块）

本目录文件为主链（在线裁决链）的安全知识库实现与生产数据。队友 clone 后按本说明即可启用。

## 一、目录组成

```
backend/
├── app/services/regulation/      安全知识库服务（RegulationKnowledgeBase，HNSW 检索）
├── causal_bayes/                 因果贝叶斯推理（Noisy-OR 聚合 + do() 干预 + 阈值裁决）
└── safety_knowledge/             知识本体 / 检索 / 情报智能体模块

data/
├── knowledge_nodes_v4.jsonl      120 个 Trusted 安全知识节点（11 域 / 19 来源，含 BGE 768 向量）
├── regulation_kb_v8/             HNSW 索引（index.bin + documents.json）
├── golden_cases_v2.json          80 条开发集检索评测基准
├── frozen_test_v1.json           42 条独立冻结测试集
├── frozen_test_results_v1.json   Frozen Test 成绩（MMR=0, FER 0.965）
├── safety_coverage_matrix_v3.json 覆盖矩阵（98.3% 意图覆盖 / 97.3% 证据覆盖）
├── retrieval_benchmark_v5.json   检索 Benchmark 结果
└── hnsw_param_test_results_v2/3.json  HNSW 参数实验数据（论文 2.2.2 支撑）
```

## 二、快速开始

```bash
# 1. 重建知识库 HNSW 索引（knowledge_nodes_v4.jsonl → regulation_kb_v8/）
python scripts/run_knowledge_retrieval.py --rebuild

# 2. 检索演示
python scripts/run_knowledge_retrieval.py --query "关闭大灯" --k 5

# 3. 运行检索评测（Golden Cases）
python scripts/s18_benchmark_v4.py

# 4. 运行 Frozen Test 独立评测
python scripts/s52_e1_evaluate.py
```

## 三、知识库在裁决链中的位置

```
用户语音 → 语义帧 → 安全知识检索向量
  → HNSW（regulation_kb_v8）→ Top-K 知识节点
  → 证据需求聚合（required_evidence ∪ 系统级强制证据）
  → Evidence Resolver → CARLA/车辆状态
  → 证据质量门控 → causal_bayes（P(Safe|E)）→ Safety Gate → PASS/REVIEW/BLOCK
```

- 知识库服务：`backend/app/services/regulation/service.py`
- 因果推理：`backend/causal_bayes/inference.py`（`decide()` 阈值 0.90/0.30，缺失证据 → REVIEW）
- 因果子图注册：`backend/causal_bayes/graph_registry.py`（HEADLIGHT_OFF 示例）

## 四、注意事项

1. `data/regulation_kb_v8/` 为构建产物，可用 `--rebuild` 从 `knowledge_nodes_v4.jsonl` 随时重建；
2. 知识节点扩展后需重新执行 `--rebuild`，新增节点进 Trusted 前必须走 `intelligence-agent/` 的审核链（Candidate → Review → Trusted），保持 Leakage=0；
3. 评测基准（golden/frozen）冻结，不得修改后重报成绩。

## 五、真实知识库启用（clone 后必做）

`data/knowledge_nodes_v4.jsonl`（120 节点）存在两个数据问题，直接作为 Trusted 知识库会加载 0 节点：

1. 节点 metadata **缺 `review_status: TRUSTED` 标记** → `load_trusted_nodes` 按 `is_trusted` 全过滤；
2. 47/120 节点含 **39 种 non-canonical 证据**（`SECURITY_STATE`、`DATA_*`、`SOFTWARE_VERSION` 等安全/数据域类型），与主系统 38 种车辆控制 canonical 证据空间冲突 → 严格校验直接抛错。

解决方案：生成**净化副本**（注入 TRUSTED 标记 + 过滤 non-canonical 证据，不改原文件）：

```bash
# 1. 生成净化副本（data/knowledge/trusted_nodes_v4_clean.jsonl，120 节点可加载）
python scripts/build_trusted_nodes_v4_clean.py

# 2. 配置 config/knowledge.yaml 指向净化副本
#    data_path: data/knowledge/trusted_nodes_v4_clean.jsonl

# 3. 重启后端，验证
#    GET /api/knowledge/status  → ready: true, node_count: 120
```

> 净化副本是生成物，不入库；`knowledge.yaml` 默认仍指向 `data/knowledge/trusted_nodes.jsonl`（不存在），本地按上面配置即可，部署时可用环境变量 `YUZHENG_KNOWLEDGE_DATA_PATH` 覆盖。

## 六、法规知识库 + 节点详情展示（新增）

- **法规库接入**：`RegulationKnowledgeBase`（`data/regulation_kb_v8`，75 条 GB 标准）已接入裁决链，每条指令响应带 `regulation_rationale`（法规依据）；`GET /api/regulation/status` 查状态。
- **证据检索页分层展示**：`/evidence` 按安全层展示命中节点（第几层命中几个）→ 选层看节点 → 点节点详情展开，可看到该节点所属意图的**安全知识命中**（📚）与**法律法规**（📜）。
- **归一化路由**：`config/request_routing.yaml` 控制 Qwen3.5 归一化；Ollama 不可用时 `fallback_mode: pass_through`（本地直通，保证链路可测）/ `uncertain`（fail-closed）。
