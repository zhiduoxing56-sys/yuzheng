# 阶段四接口说明

阶段四验收地址：`http://127.0.0.1:8765`。所有 JSON 使用 UTF-8。

## 健康检查

`GET /api/health`

返回服务、阶段和 SQLite 连接状态。

## 文本指令

`POST /api/command/text`

```json
{
  "text": "打开车门",
  "speaker_zone": "driver",
  "speaker_role": "driver",
  "state_overrides": {
    "vehicle_speed": 0,
    "gear_position": "P"
  },
  "evidence_overrides": []
}
```

`state_overrides` 是模拟车辆快照覆盖；显式 `null` 表示该状态不可用。`evidence_overrides` 仅用于本地测试多源、陈旧、不可用或完整性异常观测，例如：

状态模型包含 `emergency_flag` 和 `collision_state`；两者与障碍距离、制动状态共同作为 Cnec 的真实证据，指令中的“紧急”“立即”文字本身不会提高 Cnec。

```json
{
  "evidence_type": "vehicle_speed",
  "source": "wheel_speed_sensor",
  "value": 20,
  "age_seconds": 0,
  "available": true,
  "integrity_valid": true
}
```

响应保留阶段一所有字段，并新增：

- `query_vector`：实际 768 维归一化向量；
- `evidence_demand.vectorization_metadata`：向量实现、模型名、摘要、是否真实模型推理及降级原因；
- `retrieval_metadata`：检索实现、索引参数、节点数、耗时和降级状态；
- `candidate_evidence`：普通语义检索候选及其 `semantic_similarity`；
- `mandatory_recall_records`：每类强制证据的 `ALREADY_COVERED`、`RECALLED` 或 `MISSING` 过程；
- `quality_metrics`：ECR、ECS、EF、SAS、EAS 及短期/长期可用率；
- `evidence_subgraph`：本轮真实节点、边、缺失类型和召回元数据；
- `audit`：包含上述新增字段并纳入 SHA-256 前向哈希链。

硬门优先于软评分。高软评分与 `gate_blocked=true` 可以同时出现，但 `final_decision` 必须为 `BLOCK`。

## 当前证据

`GET /api/evidence/current`

按“证据类型 + 来源”返回各证据流最新节点，并返回节点数、类型数、短期和长期可用率。数据来自实际仓库状态，不是固定列表。

## 本轮证据子图

`GET /api/evidence/turn/{turn_id}`

返回处理文本指令时生成的 `EvidenceSubgraph`。服务重启后会从 SQLite 审计记录恢复该轮子图；不存在时返回 404。

## 索引重建

`POST /api/index/rebuild`

```json
{"exclude_types": []}
```

从证据仓库各稳定 evidence_key 的当前规范节点确定性重建索引，不把本轮 MISSING、冲突派生节点或全部历史常驻索引。运行时证据图与审计仍保留完整节点。`exclude_types` 仅用于本地演示强制补召，不应在生产配置中使用。空请求体等价于不排除任何类型。

## 索引状态

`GET /api/index/status`

返回 `implementation`、`node_count`、`canonical_node_count`、`ephemeral_node_count`、`index_update_count`、`index_rebuild_count`、`deduplicated_count`、`dimension`、`M`、`ef_construction`、`ef_search`、`top_k`、`degraded`、`degradation_reason`、`excluded_types` 和 `last_built_at`。

`canonical_node_count` 是实际常驻索引的规范节点数；`ephemeral_node_count` 是被明确排除的本轮临时节点累计数；其余三个计数分别表示稳定项更新、确定性重建和重复项去重次数。

默认参数为 `M=16`、`ef_construction=200`、`ef_search=30`、`top_k=20`。若 hnswlib 不可用，`implementation=exact_cosine_fallback`，接口和排序仍保持确定性。

## 阶段三完整轮次与推理

- `GET /api/turns/{turn_id}`：从 SQLite 返回指定轮次完整审计记录。
- `GET /api/reasoning/turn/{turn_id}`：返回横向记忆、纵向传播的支持/风险/最终调整、因果修正、Grounding Failure、越狱冲突、五维评分、置信度和实际耗时。
- `GET /api/causal/status`：返回可学习/排除样本数、候选/保留/删除边数、DAG 节点和边数、数据充分性及重建时间。
- `POST /api/causal/rebuild`：仅用于本地开发和演示，重新读取合格审计并构建因果 DAG。
- `GET /api/audits/learning-status`：返回审计质量分布、每条侧表元数据及学习资格。
- `GET /api/audits/verify-chain`：实际重算并返回 `{\"valid\": true|false}`。

`POST /api/command/text` 向后兼容阶段一、二字段，并新增 `advanced_reasoning`、`memory_propagation`、`causal_correction`、`grounding_failures`、`jailbreak_conflicts`、`jailbreak_risk`、`score_factors`、`decision_confidence`、`actionable`、`retrieval_scope` 与 `turn_timing`。模糊命令返回 `retrieval_scope=diagnostic_only`；硬门命中时 `gate_blocked=true` 且 `final_decision=BLOCK`，无论 `soft_safety_score` 多高。

`causal_correction` 额外返回 `removed_edges`、`feature_cutoff=pre_decision` 和 `used_features`。`decision.score_evaluation_mode` 正常为 `normal`；硬门命中时为 `diagnostic_after_gate`，表示软评分不参与最终裁决，前端不得把它展示为放行置信度。

## 全局车辆状态

- `GET /api/state`：返回完整模拟车辆状态，并包含 `state_epoch_id`、`started_at`、`reset_count`、`last_reset_at`、`reset_reason`。服务启动创建新纪元，reset 更新纪元和重置计数。
- `PATCH /api/state`：接受 `VehicleStatePatch`；显式 null 表示证据不可用。
- `POST /api/state/reset`：恢复确定性模拟器初始状态。

只有 `vehicle_adapter=simulator` 时允许 PATCH/reset。修改后会立即生成新的当前证据并更新规范索引。

## 复核恢复

`POST /api/turns/{turn_id}/review`

```json
{"action":"CORRECT","corrected_text":"打开左侧车窗"}
```

`action` 为 `CONFIRM`、`CORRECT` 或 `CANCEL`。只有最新结果为 REVIEW 且工作流未终止、未过期、未超过三次时可进入。CONFIRM 不补全 unknown 槽位、不删除冲突；CORRECT 创建带同一 root_turn_id 的完整重裁决子轮次；CANCEL 终止且不签发令牌。

## 一次性授权与执行

PASS 且可执行的文本响应可在 `decision.authorization_token` 返回一次原始令牌。对应 `audit.final_decision.authorization_token` 始终为 null；数据库、事件和内存缓存只保存去敏信息。

`POST /api/turns/{turn_id}/execute`

```json
{"authorization_token":"首次响应中的原始令牌","session_id":"optional-session"}
```

执行接口依次验证 HMAC、状态、过期时间和轮次/动作/对象绑定，再以最新车辆状态完整重跑裁决。状态摘要变化、新硬门或非 PASS 会拒绝并返回 `accepted=false`。复查通过后使用 SQLite 原子事务消费令牌，再调用模拟器；消费后即使适配器失败也不能重用。

授权密钥元数据包含 `key_id/key_version/created_at/fingerprint/source/status`，但健康接口只公开非敏感的 ID、版本、来源和状态。`authorization_tokens` 保存签发密钥 ID。密钥丢失或指纹变化时，旧 `ISSUED` 会原子迁移为 `REVOKED` 并追加 `KEY_INVALIDATED/TOKEN_REVOKED`；空文件、截断、非法长度或不可读文件会安全启动失败。

## 场景接口

- `GET /api/scenarios`：返回 YAML 场景清单。
- `POST /api/scenarios/{scenario_id}/load`：清理上一场景显式观测并装载状态，不裁决。
- `POST /api/scenarios/{scenario_id}/run`：装载状态后执行真实文本流水线。

场景裁决、证据图、令牌和执行反馈都来自运行时服务，不是固定响应。

## 审计、时间线与工作流链

- `GET /api/audits?page=1&page_size=20&decision=PASS&action=打开&target=车门&risk_type=车身安全&start_time=...&end_time=...`
- `GET /api/audits/{audit_id}`
- `GET /api/audits/{audit_id}/export`
- `GET /api/turns/{turn_id}/timeline`
- `GET /api/turns/{turn_id}/workflow-status`
- `GET /api/turns/{turn_id}/verify-workflow-chain`

导出内容经过统一敏感信息脱敏，并同时返回实际原审计链和该 root 工作流链的校验状态，不写死“完整”或“不可篡改”。时间线额外返回 `historical_execution_state` 和 `current_simulator_state`，明确区分历史执行快照和当前模拟器纪元。

## WebSocket

`WS /ws/pipeline/{session_id}`

文本请求通过可选 `session_id` 关联连接。事件字段为 `event_id/session_id/turn_id/sequence/stage/timestamp/duration_ms/summary/payload`。同一活动 session 的 sequence 跨请求严格递增。执行成功尾序列为 `VEHICLE_PRECHECKED/TOKEN_CONSUMED/VEHICLE_EXECUTED/AUDIT_SAVED`；适配器失败使用 `EXECUTION_FAILED`，不发送 `VEHICLE_EXECUTED`；安全复检失败在 `VEHICLE_PRECHECKED/AUDIT_SAVED` 后终止。所有 payload 统一脱敏。

## 健康与跨域

`GET /api/health` 额外返回 `model_ready`、`embedding_implementation`、`index_ready`、`index_implementation`、`vehicle_adapter`、`token_secret_source`、`token_key_id`、`token_key_version`、`token_key_status`、`revoked_tokens_on_startup`、`workflow_event_store` 和 `websocket_ready`。接口不会返回密钥内容或完整指纹。

CORS 仅允许 `http://127.0.0.1:5173` 和 `http://localhost:5173`，没有通配来源。
