# 页面切换与只读接口性能专项结果（2026-08-04）

## 结论

本轮仅调整后端只读查询、轻量接口、缓存以及前端请求编排。裁决、复核、授权与执行的业务结论未改变；冻结接口的默认路径和响应结构保持兼容。真实 HTTP 与浏览器验收中，常态冷读取均达到目标；后端进程启动后的第一次 `presentation` 读取出现过一次 569.3 ms 的磁盘冷启动离群值，随后三个未缓存轮次为 238.3–285.5 ms。

## 原始慢点与查询路径变化

- `records_for_root` 原先调用 `all_records()`，解析全部审计 JSON 后再用 Python 筛选。现在通过 `audit_list_summaries.root_turn_id` 与 `audit_records.audit_id` 直接连接，只读取当前根工作流记录。
- `workflow-status` 原先沿用完整审计记录路径。现在从摘要、复核、授权和执行表直接读取标量状态，不加载其他轮次的大 JSON。
- `presentation` 原先在组装时隐式执行全局审计链校验。现在使用最近缓存的全局结果或当前记录局部校验，并进入有界单飞缓存。
- 审计列表原先二十条携带完整 `final_decision`、证据与解释对象。前端现在使用独立 compact 接口；默认旧接口仍保持原行为。
- 时间线原先返回完整 audits 与 workflow 原始载荷。裁决页和复核页现在使用摘要接口。
- 审计详情复用同一轮次的 presentation 缓存，避免详情内部重复组装。

数据库补充了 `root_turn_id + created_at + turn_id`、`turn_id`、授权根轮次和工作流关联轮次索引。本轮未删除或改写原始审计载荷。

## 新增轻量响应

- `GET /api/audits/compact`：仅返回审计编号、轮次、时间、指令摘要、动作/目标、裁决、复核/授权/执行状态和完整性摘要。
- `GET /api/turns/{turn_id}/timeline-summary`：仅返回事件编号、轮次/父轮次、阶段、状态、时间、耗时和摘要。
- `GET /api/read-cache/stats`：只返回命中、未命中、等待、计算、失效和淘汰计数，不返回缓存内容。

选择独立扩展路由而非修改默认路由，使冻结 OpenAPI 产物与旧客户端默认行为不变。

## 真实 HTTP 性能

环境为 Windows、本地单进程 Uvicorn、SQLite、约 115 条审计记录。响应体积为完整 HTTP 响应正文，不记录授权令牌或敏感载荷。

| 数据 | 优化前 | 优化后冷读 | 优化后热读 | 体积变化 |
|---|---:|---:|---:|---:|
| presentation | 5,927.0 ms | 238.3–285.5 ms（常态）；进程首次 569.3 ms | 19.8 ms | 当前样本 369,624 B |
| workflow-status | 3,009.3 ms | 15.4 ms | 12.0 ms | 222 B |
| timeline | 3,795.8 ms / 1,607,226 B | timeline-summary 23.3 ms | 24.6 ms | 3,461 B，缩小 99.78% |
| 审计列表二十条 | 7,116.9 ms / 10,885,490 B | compact 42.8 ms | 27.2 ms | 8,813 B，缩小 99.92% |
| audit detail | 5,881.8 ms | 75.2 ms | 20.7 ms | 216,244 B |

两个相同、未缓存的 presentation 请求同时发起时，总墙钟约 897.6 ms；两次调用共享一次真实计算，缓存统计记录 `waits=1`。该样本受进程冷启动影响，但没有启动两份重复组装任务。

## 缓存与失效

后端 `BoundedSingleFlightCache` 为线程安全 LRU，最大 128 项；同键并发由 `Condition` 合并，异常不写缓存。键包括 presentation、workflow、timeline-summary 和 audit-detail。命令、复核、执行和场景写操作只失效受影响的轮次/根轮次/审计详情，不清空无关数据，也不缓存授权令牌。

真实写操作验证创建了一个受控测试工作流：原轮次 `TURN_d21198c82076`，复核子轮次 `TURN_c4390d4508f1`。复核后失效计数由 0 增至 3，执行后由 3 增至 6；最终工作流状态为 `EXECUTED`。验证脚本未输出令牌。

当前缓存是单进程内存缓存。多 worker 或多实例部署时，各进程无法共享命中与失效消息，需要迁移到带版本键或失效广播的 Redis 等共享缓存。

## 前端请求编排与页面返回

- 应用级有界缓存最大 64 项，使用 stale-while-revalidate、同键 Promise 复用、请求版本号和失效时中止，防止迟到响应覆盖新数据。
- 裁决页初次并行读取 presentation、workflow、timeline-summary 和 vehicle-state；presentation 返回不会触发第二轮相关请求。
- 复核页的三项核心读取在浏览器日志中于同一毫秒级时间窗发起，presentation 可独立先显示；工作流链不会自动读取。
- 审计列表进入时只请求 `/api/audits/compact`；全局链只在用户点击后发起，进行中状态禁止重复操作。
- 页面间预取复用同一缓存与并发去重；失败不阻止导航，不读取或缓存执行令牌。
- 浏览器从详情返回审计列表时，首次 DOM 快照已包含原二十条表格且没有“加载中”；过期数据在后台重新验证。
- 非实时页面显示“当前页面未启用实时通道”，后端健康状态独立显示。

## 剩余限制

- 进程启动后的第一次 presentation 受 SQLite 页缓存和 Python 冷启动影响，实测一次 569.3 ms，略高于 500 ms 目标；常态未缓存轮次已稳定低于目标。没有通过放宽前端超时掩盖该离群值。
- presentation 和审计详情仍返回冻结的完整对象，响应体积约 0.2–0.37 MB；本轮优先消除了其重复计算，未新增破坏兼容性的详情摘要契约。
- 前端应用缓存只存在当前标签页内存中，刷新浏览器后会重新读取；这是避免持久化敏感只读结果的有意边界。
