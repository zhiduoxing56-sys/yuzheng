# HNSW 参数扫描对照实验：原生固定 HNSW vs 规模感知自适应 HNSW

> 目的：回答"为什么需要自适应 HNSW"——在固定知识规模下，扫描 M / efConstruction / efSearch
> 三个参数，对比 **原生固定参数 HNSW（基线）** 与 **自适应参数 HNSW（本文方案）** 在
> 召回率（Recall_ANN@20）与检索时延（P95）上的差异，并用 Flat 精确检索作为召回率上限参照。

---

## 1. 实验要验证的结论（论文口径）

> 在固定规模的安全知识集合上，原生 HNSW 的检索性能对邻接度、构图宽度和搜索宽度具有
> **不同程度的参数敏感性**：邻接度 M 主要影响索引连通性与图存储开销；构图参数 efConstruction
> 影响离线图质量与构建开销；搜索参数 efSearch 直接控制在线召回率与查询时延。
> 基于该规律，本文引入**规模感知参数控制器**，以召回率为主要约束，联合检索时延、索引空间
> 与离线构建开销识别**参数收益拐点**，自动选择当前知识规模下更适宜的参数组合。

三级参照体系（每组实验同时给出）：
- **Flat 精确检索**：召回率上限（Recall_ANN@20 = 1.0），查询代价最高
- **A0 原生固定 HNSW**：θ0=(16, 200, 30)，不随规模/目标变化——清晰基线
- **A1 自适应 HNSW**：在扫描参数固定时，由控制器按边际收益拐点选择其余参数

## 3. 三组参数扫描（每点记录 R / T_mean / T_P95 / C_index / T_build）

| 扫描 | 取值 | 固定其余 |
|---|---|---|
| M（邻接度） | {8,12,16,20,24,28,32,36} | efC=200, efS=100 |
| efConstruction（构图） | {50,75,100,150,200,300,400} | M=16, efS=100 |
| efSearch（检索） | {20,30,50,75,100,150,200,300,400} | M=16, efC=200 |

### 3.1 三个参数的代价解释（不能混为一谈）

| 参数 | 主要影响 | 代价归属 |
|---|---|---|
| M | 召回率 + 查询时延 + 索引存储 | 邻接度越高，图边越多，存储与查询遍历成本上升 |
| efConstruction | 召回率 + 索引构建时间 | 固定 M 时对存储与在线查询时延影响弱；代价是**离线构图时间** |
| efSearch | 召回率 + 在线检索时延 | 基本不改变索引空间；在线阶段唯一可动态调整 |

### 3.2 自适应目标（比"三者平衡"严谨的形式化）

```
max R
s.t. T_q ≤ T_max    （在线查询时延约束）
     C   ≤ C_max    （索引空间约束）
     T_b ≤ B_max    （离线构建时间约束）
```

## 4. 自适应参数控制器（边际收益拐点判定）

对扫描参数固定时的候选组合，在 **Q_tune 集** 上：
1. 逐组构建 HNSW + 评估 (R, T, C, B)
2. 筛可行解：R ≥ R_min（默认 0.90）且 T ≤ T_max 且 C ≤ C_max；无可行解时松弛约束
3. 按召回率升序排序，对相邻组合计算**边际收益率**：
   ```
   g = ΔR / (α·ΔT + β·ΔC + ε)
   ```
4. 当 g < η（默认 0.5）→ 召回增益已不足以补偿代价增量 → 选拐点前一组参数 θ*
5. 输出 (M*, efC*, efS*) 用于当前规模下的最终评测（Q_test 集）

> 与"扫描一个参数、其余参数固定"的原生对照不同：自适应方案在同一扫描点上，
> 扫描参数取当前值 v，**其余参数由控制器联合选择**，即 (M, efC*(M), efS*(M))——
> 二者在同一横轴位置真正构成"单参数固定 vs 联合参数自适应"的严格对照。

## 5. 运行时防干扰约束（本实验已落实）

- 每配置：预热 3 轮 + 正式 10 轮，查询顺序随机化（固定种子 42）
- 固定同一嵌入向量（预计算，不经过模型缓存）
- 固定 CPU 线程（MKL_NUM_THREADS=1）、固定随机种子、禁止查询缓存
- 计时范围 = **HNSW 索引核心查询时延**（query vector 已生成 → knn_query() → Top-K IDs 返回），
  不含编码/前后处理（图上标注"P95 Query Latency (ms), HNSW 核心查询"）
- 记录 Mean / P50 / P95；PPT 画 P95，论文表报 Mean/P95

### 8.4 数据解读

- **efSearch 是最具区分度的参数**：原生 R 从 0.9850 → 1.0000，P95 从 0.149ms → 3.761ms，
  召回率—时延拐点清晰（efS≈50-75 后 R 增益 <0.15%，P95 进入 ms 级）——支持
  "搜索宽度直接控制在线召回率与查询时延"的结论
- **自适应控制器在 R≥R_min(0.90) 约束下系统性选择低时延配置**（多数点选 efS=20/30）：
  以 R 损失 ≤0.6% 换取 P95 下降 30-70%，印证收益拐点判定的有效性
- **M/efC 扫描中 R 饱和于 0.998+**（N=2326 规模下近似误差小）——这正是论文正式版
  需要 N=12200/15888 的原因：更大规模下召回率曲线将出现更明显的梯度与拐点
- 原生基线 P95 存在偶发长尾抖动（如 M=20 时 5.49ms），为系统级噪声，论文表报 Mean 时更稳
- 存储代价 C 随 M 线性增长（索引 ≈ 向量本体 + N×M×8B 邻接边），对应"邻接度影响存储"的结论

## 9. 论文/PPT 讲稿（口头版）

> 这一页回答两个问题。第一，为什么选择 HNSW？相比 IVF、IVF+PQ 与 Flat，
> HNSW 在召回率、检索速度和实时更新能力之间具有更好的综合平衡。
> 第二，为什么我们的方法优于原生 HNSW？原生算法参数固定设定，而知识库规模扩展后，
> 固定参数可能导致召回率、检索时间与存储开销失衡。因此我们设计了自适应参数选择机制：
> 在不同数据规模下自动评估候选参数组合，通过边际收益分析找到召回率提升趋缓、
> 但时延与存储代价明显增加之前的**收益拐点**，输出更合理的参数配置。
