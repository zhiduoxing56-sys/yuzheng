## 阶段一冻结修正

审核要求的三项修正已完成：

1. 无强制证据时，`evidence_coverage=null`、`evidence_coverage_applicable=false`；覆盖率因子不参与软评分，语义质量权重重新归一化为 1.0。“把那个打开”的实测软评分由旧语义下的 0.6138 降为 0.2275，不再获得虚假满覆盖加分。
2. `soft_safety_score` 表示硬门前软评分，`final_decision` 表示最终裁决；`safety_score` 和 `decision` 作为兼容字段保留并分别与新字段强制一致。`gate_blocked`、`gate_reasons` 独立返回，硬规则始终优先于软评分。
3. 显式状态覆盖 `vehicle_speed=null` 会保留为空值并生成 `MISSING` 节点；返回 `mandatory_evidence_missing=true`，命中 `MANDATORY_EVIDENCE_AVAILABLE` 并最终 `BLOCK`。

修正后的指定命令实测结果：

- `python -m compileall -q backend\app backend\tests`：退出码 0。
- `python -m pytest -v --durations=20`：18 项全部通过；修复后首轮为 `18 passed in 0.30s`，最终回归为 `18 passed in 0.38s`。
- 驻车打开车门：`soft_safety_score=1.0`，`gate_blocked=false`，`final_decision=PASS`。
- 80 km/h 行驶中打开车门：`soft_safety_score=1.0`，命中 `MOVING_DOOR_OPEN_PROHIBITED`，`final_decision=BLOCK`。
- “把那个打开”：`evidence_coverage=null`，`evidence_coverage_applicable=false`，`soft_safety_score=0.2275`，`final_decision=REVIEW`。
- 车速证据缺失时打开车门：车速节点 `MISSING`，`mandatory_evidence_missing=true`，`soft_safety_score=0.9167`，`final_decision=BLOCK`。
- 实际服务验证结束后 SQLite 共 15 条审计记录，包含历史模式记录的完整链校验为 `True`。

首次服务验证脚本受 PowerShell 本地代码页影响，曾向接口发送4条乱码文本；系统将其如实解析为未知语义并记录为 `REVIEW`。这些记录未删除或改写，以保持审计链真实性；随后改用 ASCII Unicode 转义完成了两轮正确中文四场景验证。

哈希链校验使用记录落盘时的原始 JSON 重算摘要，同时仍用当前 Pydantic 模型验证内容。这样新增兼容字段不会改变旧记录摘要，真实字段或摘要被篡改仍会被检测。
