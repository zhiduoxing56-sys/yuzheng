# 裁决、知识检索与模拟器页面精简设计

## 背景与目标

现有裁决页、知识检索页和模拟器页同时暴露了过多工程诊断信息与重复操作入口。比赛展示更需要直接回答三个问题：系统理解了什么、依据哪些安全知识作出什么裁决、当前车辆与场景处于什么状态。

本轮只调整前端信息架构和交互，不改变语义解析、知识检索、证据需求、安全门、裁决和下一轮指令上下文的后端语义。

成功标准：

1. 裁决页移除指定技术字段，并将右侧裁决枚举完整中文化。
2. 知识检索页直接展示最终知识结果；每条默认只显示核心句子，点击后查看详情。
3. 模拟器把车辆状态、CARLA 控制和补充上下文合并为一张状态表，只保留一个“应用全部设置”按钮。
4. 刷新只更新 CARLA 可回传字段，不覆盖 CARLA 不支持的手动上下文，也不冲掉尚未应用的本地修改。
5. 选择场景或一键重置时才允许覆盖整张状态表。

## 现状与约束

- 裁决页由 `DecisionPage`、`SemanticFrameDisplay`、`RequestRoutingDisplay` 和 `DecisionResultDisplay` 组合。
- 知识检索页已经取得正式命中、诊断排名、上下文投影和查询向量元数据，但当前按 K0–K3 展示检索过程。
- 模拟器页当前分为实时画面、CARLA 支持控制和 CARLA 不支持上下文三列，并存在多个独立“应用/设置/保存”按钮。
- CARLA 物理状态通过 `/api/state` 等接口控制和回读；补充上下文通过 `/api/state/simulation-context` 保存，作为下一次指令的 SIMULATION 证据。
- 现有后端没有一次性原子提交全部物理控制与补充上下文的统一接口。前端需要编排现有接口，并明确展示部分成功结果。
- 工作区已经存在与本任务无关的未提交删除，实施时必须保持不动。

## 方案对比

### 方案一：统一状态表，当前值直接编辑（采用）

- 优点：状态与设置合一；信息密度适中；只需要一个统一应用入口。
- 缺点：前端需要维护“已回读值、草稿值、脏字段”三类状态，提交编排稍复杂。

### 方案二：当前状态列与目标设置列并排

- 优点：真实值和目标值边界最清楚。
- 缺点：重复展示同一字段，页面仍显拥挤，不符合合二为一的目标。

### 方案三：按 CARLA 能力拆成两个折叠区

- 优点：技术能力边界最明显。
- 缺点：仍然延续两套表单，无法形成完整车辆状态视图。

## 推荐方案

采用方案一。统一状态表中的每一行都有稳定字段定义、中文名称、编辑控件、单位、来源和能力类型。输入控件在未修改时就是最新当前值；用户修改后成为待应用值，并显示“待应用”标记。这样不额外复制一列，也能区分真实回读与尚未生效的草稿。

## 详细设计

### 一、裁决页面

#### 左侧语义信息

完全移除 `RequestRoutingDisplay`，不再渲染左下角“理解过程”。语义帧摘要中移除：

- 规范化指令；
- 整体语义置信度；
- 整体歧义度；
- 复核原因。

每个意图卡片中移除：

- 风险等级；
- 风险标签。

其余已有字段维持现状，空值继续沿用当前隐藏或占位规则。本轮不删除后端字段、不修改 TypeScript 合同，仅停止展示。

#### 右侧裁决中文化

增加统一的展示映射，不直接输出后端英文枚举：

| 字段 | 英文值 | 中文展示 |
| --- | --- | --- |
| 证据对齐/评分/最终裁决 | `PASS` | 允许执行 |
| 证据对齐/评分/最终裁决 | `REVIEW` | 需要人工复核 |
| 证据对齐/评分/最终裁决 | `BLOCK` | 拒绝执行 |
| 证据对齐 | `NOT_APPLICABLE` | 不适用 |
| 裁决来源 | `SAFETY_GATE` | 硬性安全门 |
| 裁决来源 | `EVIDENCE_ALIGNMENT` | 证据对齐 |
| 裁决来源 | `SAFETY_SCORE` | 安全评分 |
| 裁决来源 | `RUNTIME_CAPABILITY` | 运行能力约束 |
| 裁决来源 | `VOICE_TRUST` | 语音可信约束 |
| 裁决来源 | `ZONE_PERMISSION` | 区域权限约束 |
| 裁决来源 | `USER_REVIEW` | 用户复核 |
| 裁决来源 | `LEGACY_COMPATIBILITY` | 兼容记录 |

安全门继续显示“已通过/已阻断/暂无结果”。合并原因优先显示后端已有中文文本；若文本中嵌有上述枚举，则只替换已知标记。未知枚举显示“未识别状态”，避免将技术英文直接暴露在主页面。

诊断评分保持默认折叠，不改变计算或裁决地位。

### 二、安全知识检索页面

#### 最终结果列表

将“知识检索分层”改名为“知识检索结果”，删除 K0、K1、K2、K3 的分层按钮、分层弹窗及以下统计：

- 合法知识节点；
- 正式前五返回；
- 阈值命中；
- 检索状态。

结果数据以本轮正式 `knowledge_hits` 为准，并用 `raw_results`/诊断节点中的完整字段按 `node_id` 补全详情。按正式命中顺序去重，不把仅诊断、低于阈值或未进入正式结果的节点混入列表。

每条结果默认只显示一个核心句子：优先 `semantic_description`，为空时依次回退到 `title`、`clause` 和“该知识节点暂无摘要”。点击整条结果展开，再次点击收起。展开内容包括：

- 标题；
- 适用条件；
- 必需证据；
- 可选证据；
- 来源；
- 章节；
- 条款。

默认态不显示节点编号、HNSW 标签、排名、相似度、阈值结果、信任等级和结果范围。无正式命中时显示“本轮未找到相关安全知识”。多意图轮次继续保留意图切换。

#### 右侧知识查询

右侧“知识查询”移除：

- 编码模型；
- 向量维数；
- 正式前五/搜索范围；
- 相似度阈值。

保留原始用户指令、意图编号、规范动作/对象、区域、知识检索查询句和证据检索查询句。查询上下文投影继续保留，因为它解释了哪些车辆与场景事实进入查询；其中技术枚举使用现有中文映射。

### 三、模拟器页面

#### 页面结构

保留 CARLA 实时画面。原“当前车辆与传感器状态”“物理场景控制”“仿真补充上下文”合并为一个“车辆与场景状态”区域。

顶部操作只保留：

- 场景预设选择；
- “载入场景”；
- “刷新状态”；
- “一键重置”。

整个状态区只保留一个主操作按钮：“应用全部设置”。“载入场景”和“一键重置”属于数据装载/恢复操作，不作为字段应用入口。

#### 统一状态模型

前端维护：

- `baseline`：最近一次真实回读或已保存的生效值；
- `draft`：当前表格显示和编辑的值；
- `dirtyFields`：用户修改但尚未应用的字段集合。

字段按展示分组，但仍属于同一张表：

1. 车辆：车速、挡位、前照灯、车门、车窗、制动、系统模式等。
2. 传感器：前后障碍距离、碰撞状态、周边目标、道路状态等。
3. 环境：天气、时段、环境照度、能见度、降水、雾。
4. 周边目标：区域、类型、距离、相对速度、运动状态、风险等级。
5. 道路与授权：道路状态、湿度、摩擦系数、系统模式、授权声明。
6. 场景控制：交通灯和障碍物目标状态。

每行显示中文字段名、一个值控件以及“CARLA 回传”“CARLA 控制”“仿真上下文”或“只读传感器”的来源提示。CARLA 当前只读传感器使用只读文本控件；可控制物理字段和补充上下文字段使用下拉框、数字输入框或开关。

#### 刷新规则

“刷新状态”只调用 CARLA 物理状态回读：

- 未修改的 CARLA 字段同步为最新值；
- 已标记为待应用的 CARLA 字段保留用户草稿，并显示待应用状态；
- CARLA 不支持的补充上下文不重新读取、不清空、不恢复默认值；
- 不再让两秒自动刷新覆盖正在编辑的表单。若保留自动轮询，也只能更新只读传感器和未修改字段，并遵守相同合并规则。

#### 载入场景与重置

“载入场景”调用正式场景接口，然后同时回读 VehicleState 和 simulation-context，用返回值覆盖整张表，清空所有待应用标记。

“一键重置”恢复 CARLA 车辆默认状态并清空/恢复补充上下文默认值；完成后同时回读两类数据，覆盖整张表并清空待应用标记。重置按钮使用现有确认交互或增加一次轻量确认，防止误触。

#### 应用全部设置

点击“应用全部设置”后，前端按字段能力拆分草稿：

1. 可由 `/api/state` 修改的字段合并成一次 `VehicleStatePatch`。
2. 天气、交通灯和障碍物等使用现有 CARLA 专用接口；障碍物按目标状态执行清除或生成，避免每次应用无条件重复生成。
3. CARLA 不支持字段转换成 `EvidenceObservationInput[]`，通过 `replaceSimulationContext` 一次保存。
4. 所有提交结束后回读 CARLA 物理状态和补充上下文，更新生效值。

提交采用分组结果汇总：全部成功时清空所有待应用标记；部分失败时只清除成功字段，失败字段保留草稿与“应用失败”提示，并在页面底部列出失败分组。前端不得把部分成功显示成全部成功。

补充上下文保存后只影响下一次新指令的裁决，不追溯修改已经产生的轮次。

## 异常与边界处理

- 裁决枚举为空时显示“暂无结果”；未知枚举不猜测安全含义。
- 知识节点缺少摘要时使用明确回退顺序；详情缺失字段整行隐藏。
- 多意图知识结果按 occurrence 隔离，切换意图时收起已展开项。
- 用户存在待应用字段时刷新，不覆盖这些草稿。
- 场景加载或重置失败时保留当前表格，不能清空成默认值并误报成功。
- 应用期间禁用重复提交；离开页面前若存在待应用内容，可提示尚未应用。
- 数值字段在提交前校验范围和空值，错误定位到具体行。

## 测试策略

### 裁决页

- 断言“理解过程”和七个指定字段不再出现。
- 覆盖 PASS、REVIEW、BLOCK、NOT_APPLICABLE 和全部裁决来源中文映射。
- 验证授权、复核、确认和执行流程无回归。

### 知识检索页

- 断言 K0–K3、四项统计和四项向量参数不再出现。
- 验证只展示正式命中、按正式顺序去重。
- 验证默认只显示核心句子，点击整行展开/收起详情。
- 覆盖空结果、字段缺失和多意图切换。

### 模拟器页

- 验证车辆状态、CARLA 控制和补充上下文出现在同一状态表。
- 验证只有一个“应用全部设置”字段提交按钮。
- 验证刷新更新 CARLA 回传字段，但保留补充上下文和待应用草稿。
- 验证载入场景和重置会覆盖整张表并清空脏状态。
- 验证一次应用正确拆分物理 patch、CARLA 专用控制和 simulation-context。
- 验证部分失败只保留失败字段，并展示准确反馈。
- 验证补充上下文只进入下一次新指令。

### 最终验证

- 前端 TypeScript 类型检查、单元测试和生产构建。
- 使用项目指定 Python 环境运行相关后端回归测试。
- 桌面、常见笔记本和窄屏浏览器视觉验收。
- 真实执行一个 PASS、一个 REVIEW 和一个 BLOCK 轮次，确认裁决事实未改变。

## 风险与待确认项

- 现有 API 不提供跨物理状态与补充上下文的后端事务，因此“应用全部设置”是一次用户操作、多个受控请求，而不是数据库级原子提交。页面必须诚实展示部分失败。
- 障碍物当前是生成/清除命令，不是普通状态 patch；实施时需要用目标状态与已回读对象进行差异判断，防止重复生成。
- 若产品最终要求所有字段绝对原子更新，需要新增后端组合接口，超出本轮纯前端调整范围。
