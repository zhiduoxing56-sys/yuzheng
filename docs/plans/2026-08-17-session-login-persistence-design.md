# 会话级登录持久化设计说明

## 背景与目标

当前前端登录状态仅保存在 React 内存中，刷新页面后会回到登录页。目标是在同一次浏览器会话中保留登录状态；用户主动退出或关闭浏览器后，需要重新登录。

## 现状与约束

- 前端通过 `AuthProvider` 和 `ProtectedRoute` 管理登录拦截。
- 当前登录没有真实的后端认证令牌，不能保存账号、密码或任何敏感凭据。
- `sessionStorage` 会在浏览器会话结束后自动清除，符合关闭浏览器后重新登录的需求。

## 方案对比

### 方案一：sessionStorage 登录标记

- 优点：刷新后保留；关闭浏览器后自动失效；退出登录可立即清除。
- 缺点：不是跨浏览器重启的长期登录。

### 方案二：localStorage 登录标记

- 优点：长期保留。
- 缺点：关闭浏览器后仍保持登录，不符合需求。

### 方案三：仅内存状态

- 优点：实现最简单。
- 缺点：刷新即退出，不能满足需求。

## 推荐方案

采用方案一。认证状态初始化时读取会话存储；登录成功时写入标记；退出时删除标记。路由保护逻辑保持不变。

## 详细设计

### 架构与数据流

`AuthProvider` 是唯一读写 `sessionStorage` 的组件。应用启动时从固定键读取布尔标记，登录后写入，退出时删除；`ProtectedRoute` 继续只依据 `authenticated` 决定跳转。

### 异常与边界处理

浏览器禁用或无法访问会话存储时，读操作按未登录处理，写入失败不阻断当前会话内的登录状态；关闭浏览器后的自动失效仍由浏览器负责。

### 测试策略

覆盖初始化恢复、登录写入和退出清除三种行为，并执行前端类型检查与测试。
