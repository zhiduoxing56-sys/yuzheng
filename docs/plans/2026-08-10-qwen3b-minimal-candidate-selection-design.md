# qwen2.5 3B 极简候选多选对照实验设计

## 背景与目标

`qwen2.5:1.5b` 延迟达标但候选裁决能力未通过。使用同一 v1.1 召回器、同一 60 条能力集，仅测试 `qwen2.5:3b-instruct-q4_0`，判断把生成任务缩到候选 ID 多选后，能力提升是否值得额外推理成本。

## 现状与约束

- 第一阶段配置固定为 `test-results/intent-recall-v1_1/config_v1_1.yaml`。
- 不修改锚点、召回算法、1.5B 实验、正式后端、安全链或 CARLA。
- 模型只看到原文与 Top 8 候选的 ID、中文名、最强 1～2 条锚点。
- 模型 Schema 只有 `{"intent_ids": [...]}`，不生成状态、证据、参数、确认、安全信号或解释。
- 只调用 3B；不调用 1.5B 或 7B。

## 方案对比

### 方案一：原地修改 1.5B 实验
- 优点：文件少。
- 缺点：破坏已验收基线，无法可靠回放。

### 方案二：抽取共用裁决框架
- 优点：减少重复代码。
- 缺点：本轮会扩大改动范围，并可能改变 1.5B 基线行为。

### 方案三：独立 3B 极简实验（采用）
- 优点：隔离模型、提示、Schema、输出与测试产物；对照最清晰。
- 缺点：少量评测代码重复。

## 详细设计

### 数据流

原文 → v1.1 Top 8 召回 → 3B 输出有序 `intent_ids` → 严格候选/Schema 校验 → 程序派生状态、空参数、拼音确认 → 原样附加 `security_signals`。

### 模型外派生

- 空数组：`NO_MATCH`。
- 非空且没有拼音确认：`OK`。
- 非空且满足真实拼音支持锚点、字面差异阈值：`REVIEW`，确认文本直接取支持锚点。
- 每个选中 ID 转成 `{"intent_id": id, "params": {}}`；不生成 `evidence_text`。
- 安全信号只取第一阶段结果，绝不进入模型提示。

### 异常边界

动态 JSON Schema 将 ID 限制为当前候选，禁止额外字段和重复 ID。Schema/JSON/请求失败时不猜测候选，记录错误并使用空数组。模型输出顺序原样保留，用于真实测量顺序能力。

### 测试策略

1. 先离线确认 60 条期望目标都在 Top 8。
2. 显式卸载 3B，记录一次冷请求；随后保持 `keep_alive=-1`。
3. 运行同一 60 条能力集，按意图集合、单意图、多意图集合、多意图顺序、空数组拒识和强制归类统计。
4. 运行至少 50 次独立热请求，统计召回、Ollama、首 token、完整链和 token。
5. 与 1.5B 已固化结果并列；若能力仍近似 1.5B，停止且不测试 7B。

## 生死门

3B 应显著提升单意图和多意图，且不能频繁强制归类无关输入；热态模型 P95 目标不高于 2 秒，全链 P95 尽量不高于 2.5 秒。任一关键能力仍不可用则不进入正式系统。
