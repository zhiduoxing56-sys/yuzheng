# 裁决、知识检索与模拟器页面精简实施计划

> 设计依据：`docs/plans/2026-08-17-frontend-information-simplification-design.md`。本计划先锁定展示行为，再重构模拟器状态模型；不改变后端裁决、检索和证据语义。

## 阶段 0：基线与改动边界

1. 记录 `DecisionPage`、`EvidencePage`、`CarlaPage` 的现有桌面与窄屏截图。
2. 运行相关前端测试，保存当前失败项，避免把工作区已有问题归因于本轮修改。
3. 固定三个真实轮次：PASS、REVIEW、BLOCK；保存改动前的语义帧、正式知识命中和最终裁决。
4. 确认只修改本计划列出的前端文件和测试；保持当前工作区已有删除不动。

## 阶段 1：补充展示映射与测试

1. 在 `DecisionVisuals` 或独立 formatter 中增加裁决、证据对齐和裁决来源的中文映射。
2. 为 PASS、REVIEW、BLOCK、NOT_APPLICABLE、空值和未知值先补单元测试。
3. 增加合并原因中已知枚举的安全替换测试，禁止误改普通英文或自由文本。
4. 保持原始合同值不变，映射只发生在展示层。

## 阶段 2：精简裁决页面

1. 从 `DecisionPage` 移除 `RequestRoutingDisplay` 的导入和渲染。
2. 从 `SemanticFrameDisplay` 移除规范化指令、整体置信度、整体歧义度、复核原因。
3. 从意图卡移除风险等级和风险标签。
4. 将右侧证据对齐、评分判断、最终裁决、裁决来源和合并原因切换为中文 formatter。
5. 更新 `semanticFrameDisplay` 和裁决视觉状态测试，验证授权、复核与执行入口仍正常。
6. 清理失去引用的局部格式函数；若 `RequestRoutingDisplay` 在其他页面仍使用则保留组件文件，否则单独确认后再删除。

## 阶段 3：把知识分层改为最终结果列表

1. 在 `EvidencePage` 建立 `finalKnowledgeResults` 派生数据：以 `knowledge_hits` 顺序为准，按 `node_id` 去重，并从已有完整节点集合补齐详情。
2. 删除 `KnowledgeLayer`、K0–K3 派生逻辑、分层选择状态和分层弹窗。
3. 将左侧标题改为“知识检索结果”。
4. 实现整条可点击的折叠结果项：默认只显示核心句子，展开后显示业务详情。
5. 删除合法节点、正式前五、阈值命中和检索状态统计。
6. 从知识查询卡删除编码模型、向量维数、搜索范围和相似度阈值。
7. 保留多意图切换、查询正文和上下文投影；切换意图时清理展开状态。
8. 更新 `evidenceHnswPage` 测试，覆盖正式顺序、去重、展开/收起、空结果和多意图。

## 阶段 4：建立模拟器统一状态模型

1. 定义稳定的状态字段描述表：字段键、中文名、分组、控件类型、单位、能力类型、读写接口和校验规则。
2. 将现有 `weather`、`gear`、`speed`、`context` 等离散 state 合并为统一 `baseline` 和 `draft`。
3. 增加 `dirtyFields` 与逐字段错误状态；任何用户编辑只更新 draft 并标记待应用。
4. 编写 VehicleState 和 simulation observations 到统一 draft 的双向映射测试。
5. 明确同名字段的真值优先级，例如物理天气与补充时段不得互相覆盖。

## 阶段 5：重构模拟器页面结构

1. 保留 CARLA 直播画面，把原三列控制区域替换成一个“车辆与场景状态”表。
2. 按车辆、传感器、环境、周边目标、道路与授权、场景控制分组渲染同一字段表。
3. 可编辑字段使用下拉框、数字框或开关；只读传感器使用只读值。
4. 每行展示来源/能力标签和待应用/失败状态，不再重复展示独立当前状态卡。
5. 删除每个字段旁的应用、设置、生成、清除、保存上下文按钮。
6. 页面只保留一个主提交按钮“应用全部设置”。
7. 顶部保留“载入场景”“刷新状态”“一键重置”和“前往裁决页”。
8. 调整 `visual-pages.css`，保证桌面表格紧凑、窄屏按组堆叠且控件可操作。

## 阶段 6：实现刷新、场景与重置语义

1. 将刷新动作改为只合并 CARLA VehicleState。
2. 刷新时仅覆盖未变脏的 CARLA 字段；补充上下文字段和所有待应用草稿保持不变。
3. 删除会覆盖表单的无条件两秒回填；如保留轮询，仅更新只读传感器和未变脏字段。
4. 载入场景后并行回读 VehicleState 与 simulation-context，成功后整体替换 baseline/draft 并清空脏状态。
5. 一键重置增加确认，依次恢复物理状态与补充上下文；完成后整体回读。
6. 任一整体装载失败时保留原表格并显示错误，不构造伪成功状态。

## 阶段 7：实现“应用全部设置”

1. 从 dirtyFields 中拆分 VehicleStatePatch、交通灯、障碍物和 simulation-context 四类操作。
2. VehicleState 可写字段合并成一次 patch；补充上下文合并成一次 replace。
3. 交通灯仅在相关字段变化时提交。
4. 障碍物用目标状态执行差异更新，避免重复生成；选择“无”时清除已有测试障碍物。
5. 并发或受控串行执行互不依赖的分组请求，收集每组成功与失败结果。
6. 完成后分别回读物理状态与补充上下文；只清理成功字段的 dirty/error 状态。
7. 全部成功显示统一成功消息；部分失败列出具体分组，失败草稿继续保留。
8. 应用期间禁用场景、刷新、重置和再次提交。

## 阶段 8：测试与回归

1. 扩展 `carlaScenarioContext.test.tsx`：统一表格、唯一应用按钮、刷新保留上下文、刷新保留脏字段。
2. 增加载入场景和一键重置覆盖全表的测试。
3. 增加统一提交拆分、无变化不请求、部分失败和障碍物不重复生成测试。
4. 验证保存的 simulation-context 会被下一条新指令读取，但不会修改历史轮次。
5. 运行前端类型检查、目标测试、全量测试和生产构建。
6. 使用 `D:\software\anaconda\envs\yuzheng311\python.exe` 运行相关后端状态、场景和裁决回归测试。
7. 执行 `git diff --check`，检查只改计划范围内文件。

## 阶段 9：浏览器验收

1. 裁决页分别打开 PASS、REVIEW、BLOCK 轮次，确认指定字段消失且主裁决全部中文化。
2. 知识页验证默认只显示每条核心句子，点击可查看详情，且不出现 K0–K3 和检索参数。
3. 模拟器修改一组物理字段和一组补充字段，只点击一次“应用全部设置”，确认两类状态均生效。
4. 修改但不应用一个字段，再刷新，确认草稿不丢失。
5. 修改补充上下文后反复刷新 CARLA，确认补充字段保持不变。
6. 载入另一个场景和执行一键重置，确认两次都会完整更新整张表。
7. 在常见笔记本宽度和窄屏下检查表格、滚动、按钮、错误信息和键盘焦点。

## 完成定义

- 用户指定的裁决字段全部不再显示，右侧业务值不暴露英文枚举。
- 知识页仅展示正式最终结果，默认一句、点击详情。
- 模拟器状态与控制为一张表，字段提交只有一个应用按钮。
- 刷新、场景载入、重置和应用四种操作符合已确认的数据覆盖规则。
- 前后端相关回归、生产构建和浏览器视觉验收全部通过。
