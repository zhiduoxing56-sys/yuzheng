# 证据检索页面四层折叠列表设计

## 范围

本轮只重构 `frontend` 的证据检索页面。删除二维、三维图谱渲染及其依赖，不修改后端接口、冻结契约、轮次状态或其他业务页面。

## 单向依赖

`EvidencePage` 只负责路由轮次、数据钩子、节点选择和组件编排。`evidenceLayerAdapter` 是唯一解释证据子图、检索摘要和轮次展示字段的模块，产出四层列表、检索流程、全局统计、关系摘要、缺失摘要与诊断项。筛选钩子只对适配结果做纯筛选。展示组件只消费适配类型，不互相导入，也不持有接口请求或图形资源。

因此依赖方向固定为：页面 → 钩子/适配器 → 契约；页面 → 展示组件 → 适配结果类型，不存在循环依赖。

## 数据口径

- 四层只接受后端 `security_rank` 的 0、1、2、3；无法分类的节点不被猜测归层，并生成诊断项。
- 冲突节点只来自两端均存在的 `CONFLICTS` 边；冲突不是质量状态。
- TopK 和强制补召分别来自 `final_top_k_node_ids` 与 `mandatory_supplemented_node_ids`。
- 关键证据只来自轮次展示或高级推理中的明确节点引用，不把“必查”或“冲突”自动等同为关键证据。
- 缺失原因与裁决影响只展示后端已有文字；缺少时明确显示“后端未提供”。
- 复杂值仅生成安全、有限长度的单行摘要；完整值继续由节点详情接口展示。

## 交互

四层默认全部折叠，切换轮次时重置搜索、筛选、展开状态和节点选择。展开后使用统一表格；窄屏变为卡片。点击行、证据名称、冲突或规则关系端点时，通过既有节点详情接口打开抽屉。高级推理保持按用户展开后才请求。

## 验收

适配器覆盖正常、空图、重复节点、无效节点、悬空边、未知状态/关系、未分类层、复杂值、搜索、全部筛选和统计优先级。随后运行前端测试、类型检查和构建，并在真实后端轮次上检查允许、复核、阻断、缺失、冲突、必查、抽屉、路由恢复与响应式布局。
