# 本地小模型候选裁决器 v1 设计说明

## 目标与边界

独立实验链只执行：原始输入 → 第一阶段 v1.1 Top 8 → `qwen2.5:1.5b` 候选选择 → 严格校验 → 正交附加安全信号与确定性拼音复核。不得导入或修改正式 `SemanticFrame`、parser、pipeline、安全裁决、CARLA 或前端。

## 接口方案

优先使用 Ollama `/api/chat` 的动态 JSON Schema `format`，并同时使用短系统提示。请求开启流式 NDJSON，以首个非空 `message.content` 块测量 TTFT；最终块读取 Ollama 的总时长、加载时长、提示 token、生成 token 和生成时长。`keep_alive=-1` 使 1.5B 在测试期间常驻，`temperature=0`、`num_predict=128`、`num_ctx=2048`，不请求解释或思考。

备选方案一是非流式结构化输出，校验简单但无法实测 TTFT；备选方案二是 `format="json"` 后程序校验。仅当本机结构化 Schema 探针失败时才使用 JSON 模式，不更换模型。

## 最小提示

系统提示只说明：从所给候选中选零至多个、按原文顺序、不得猜测、NO_MATCH/REVIEW 规则、证据必须复制连续原文、只输出 Schema。用户消息是紧凑 JSON，仅含 `text` 和八个候选的 `id/name/anchors`，每个候选最多两条锚点。安全信号不进入提示。

## 校验和确定性后处理

动态 Schema 将 `intent_id` 限定为本轮候选枚举，`params` 禁止任何属性。程序再次校验：状态枚举、数组、候选约束、空对象、连续原文证据、重复项、NO_MATCH 空数组及顺序。非法输出不重试、不猜测，降为 `REVIEW` 和已验证子集。

安全信号从第一阶段原样抽取并附加，模型无权修改。拼音复核仅在模型已选择候选后运行：从该候选真实支持锚点中计算字面与拼音相似度；当拼音显著更强且字面存在明显差异时，将状态设为 `REVIEW`，`suggested_text` 直接复制该真实锚点，不让模型生成纠错文本。

## 测试与生死门

先卸载 1.5B，记录一次冷请求；随后预热并常驻。运行五条固定输入、第一阶段 25 条压力输入、至少 20 条第二阶段新增输入，并用至少 50 次不同输入的热请求统计 TTFT、Ollama 请求、生成和全链 P50/P95/最大值。若热请求 P95 明显高于 2 秒，或多意图/NO_MATCH 明显不可用，则立即停止，不测试 3B/7B，不接正式系统。
