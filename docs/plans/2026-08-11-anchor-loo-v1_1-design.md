# 意图锚点集 v1.1 全量留一诊断设计

## 边界

- 冻结输入：`挂靠/intent_anchor_set_v1_1.yaml`。
- 只新增独立诊断代码和 `test-results/anchor-loo-v1_1/` 结果。
- 不修改锚点、第一阶段召回算法、RRF 参数或任何阈值；不调用 Ollama；不接正式后端、安全链、SemanticFrame 或 CARLA。

## 方案选择

采用“已有缓存 + 查询自身索引屏蔽”方案。加载现有第一阶段召回器及其归一化 BGE 锚点矩阵；某条锚点作为查询时直接复用该行向量，语义分数用矩阵乘法计算，字面与拼音仍调用冻结实现，并在三路分数中把该条锚点索引设为负无穷。这样不会逐条重编码锚点库，也不会因构造临时 YAML 改变索引顺序。

未采用两种替代方案：逐条重建召回器会重复编码并引入缓存生命周期；为每条样本复制删减锚点文件会改变输入且难以证明只屏蔽自身。

## 正交容器

正式意图与“已知车控旁路”继续使用冻结的三路目标排名和 RRF 融合。安全注入不进入语义候选竞争，按第一阶段安全信号检测逻辑单独屏蔽自身后评估是否仍能召回“安全注入”。总体统计是两类正交容器结果的汇总，同时分别报告正式意图、旁路与安全注入。

## 诊断数据

每条锚点保存三通道的正确目标排名、原始最高分、通道 Top1、第一第二目标分差、正确目标最强支持锚点；融合保存 Top1/Top8、正确排名、支持通道数、RRF 分数差及支持锚点。

P0/P1/P2 按任务定义直接判定。P3 的“低间隔”不预设阈值：先完成全部留一结果，再取语义候选容器中 Top1 正确样本的融合 Top1-Top2 分差第 10 分位数作为诊断边界；该边界只用于标注，不改变召回输出。其余为 P4。

高风险分类根据现有目标 ID、意图卡片名称/动作/对象诊断：动作反向、相邻对象、同对象不同动作。质量问题只标注“疑似”，修订原因严格限制为用户给定的七类文本，不做任何自动修改。

## 输出与核验

生成 `summary.json`、`per-intent-stats.json`、`all-anchor-results.json`、`confusion-pairs.json`、`high-risk-confusions.json`、`repair-candidates.json`、`repair-candidates.csv`、`README.md`。运行前后计算冻结 YAML SHA256；脚本若发现摘要或扁平化顺序不一致立即失败。
