# Full NLU 人工浏览与复核材料 v1 设计说明

## 背景与目标

基于已验收的 `full_nlu_baseline_v2`，生成两个只读观察工作簿及对应 JSON 索引。工作簿不构成新数据真值，不改变任何样本、映射、注册表、schema、原始公开数据或人工种子。

## 输入与只读边界

- `full_nlu_canonical_raw_pool_v2.jsonl`
- `sample_mapping_metadata_v2.jsonl`
- `source_provenance_v2.jsonl`
- R3 注册表及现有 baseline_v2/audit_v3 报告
- 输入文件在生成前后均校验 SHA256。

## 方案对比

### 方案一：单脚本直接生成（采用）

- 直接从冻结输入构造筛选视图和稳定分层抽样。
- 不落地中间标签表，不产生平行数据真值。
- 工作簿、JSON 索引和数量门可一次完成并复验。

### 方案二：先导出中间 CSV

- 易调试，但中间文件容易被误认为新语料资产，增加同步和溯源风险。

### 方案三：人工拼装工作簿

- 灵活但不可重复执行，无法可靠保证 20,899 条视图数量与 SHA256 追溯。

## 详细设计

### 全量浏览包

四个控制范围工作表构成互斥完整分区，总和严格为 20,899。正式正样本、需要人工复核、多意图、歧义、缺槽是同一 canonical pool 的交叉过滤视图。子意图 JSON 原样展示，并增加只存在于 Excel 的人工可读展开列。

### 重点复核包

- 安全边界按原始编号合并 57 occurrence 为 55 条唯一样本。
- 610 条正式正样本按 R3 的 71 项正式意图顺序分组。
- 已知但不开放按 `规范对象 + 控制属性 + 规范动作` 聚合，稳定抽样；重点能力另列覆盖矩阵。
- 非控制、未知、复核原因、多意图、歧义与缺槽均只使用现有标签、元数据、溯源和审计原因分组，不重新解释或映射。
- 所有抽样按 canonical 顺序和固定配额完成，不调用随机数。
- 所有“人工最终决策”“人工备注”单元格保持为空。

### 格式

数据表冻结首行、启用筛选、自动换行并设置受控列宽。仅使用统一的浅色标题和边框辅助阅读，不用颜色表达标签含义。

### JSON 索引

每个索引记录工作表、过滤条件、视图/抽样数量、canonical pool SHA256、生成时间、脚本版本和最终 Excel SHA256。索引明确声明工作簿只是观察视图。

## 异常与验收门

- 四种控制范围必须为 `2071 / 3231 / 8682 / 6915`，合计 20,899。
- 正式正样本必须为 610。
- 安全边界唯一待复核样本必须为 55，原 occurrence 必须为 57。
- canonical、metadata、provenance 必须按样本编号一一对应。
- 工作簿抽检值、筛选数量、人工填写列空值、公式错误扫描和所有工作表渲染必须通过。
- 任一门失败即停止，不输出合格索引。
