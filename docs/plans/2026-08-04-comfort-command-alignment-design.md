# 低风险舒适指令证据对齐修复设计

## 背景与根因

真实轮次 `TURN_744e16b66cde` 中，“打开空调”被正确识别为 R1，必查证据和缺失证据均为空，安全评分为 0.949、评分结论为 PASS、安全门未阻断。但质量模块在没有必查证据时仍使用检索到的通用场景证据计算 EAS=0.805546，并进入 `EVIDENCE_REVIEW` 分支；统一保守合并因此将 PASS 提升为 REVIEW。

## 方案比较

1. 降低全局 EAS 阈值：改动小，但会同时放松车门、驾驶控制等高风险动作，不采用。
2. 为每个舒适动作硬编码最终 PASS：会绕过语音可信、冲突和安全门，不采用。
3. 让证据对齐显式服从“是否存在必查证据”（采用）：无必查证据时保留诊断指标，但路由固定 PASS，前端显示“不适用”；有必查证据时继续执行原保守路由。其他独立约束仍可提升或阻断。

## 后端设计

- 普通空调开关、温度与风量操作使用 R1 舒适功能配置，不声明必查证据。
- 质量模块在 `required_types` 为空时保留 EAS 数值供技术诊断，但将 `evidence_alignment_route` 固定为 `EVIDENCE_PASS`；`evidence_coverage_applicable=false` 是“不适用”的冻结契约标记。
- `merge_decision` 不新增第四种路由，避免破坏冻结模型；不适用不会提升最终等级。
- 只要语义不完整、语音可信不足、证据/声明冲突或安全门命中，现有独立来源仍可产生 REVIEW/BLOCK。
- 新增独立的“前挡风除雾”语义目标和证据需求。浓雾下关闭除雾由安全门单独检查，不与普通空调开关共享规则。
- 高风险动作有必查证据时继续使用原 EAS 阈值和保守合并。

## 前端设计

- 裁决摘要并列展示：安全评分与评分判断、证据对齐判断、最终裁决。
- 若必查证据为空，显示“证据对齐：不适用（本指令没有必查证据）”；否则映射 PASS/REVIEW/BLOCK。
- 根据评分判断与最终裁决差异生成结构化中文提升原因；原始 `decision_merge_reason` 和长解释移到“技术详情”。
- 车辆状态按动作/目标映射；普通空调没有后端状态字段时只显示“空调状态未接入”，不拿车门、挡位等无关状态填充。
- 复核提交空闲态显示“等待复核”；执行空闲及 `NOT_EXECUTED` 显示“尚未执行”。

## 测试

- 覆盖明确空调、行驶中空调、模糊指令、低可信语音、浓雾关闭前挡风除雾、传感器冲突六类场景。
- 保留并运行既有高风险安全门、证据质量、冻结契约和全量前后端测试。
- 最后通过真实 HTTP 创建“帮我打开空调”轮次，并在真实浏览器核对三层判断和车辆状态提示。
