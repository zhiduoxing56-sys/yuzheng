# 阶段四冻结安全修复设计

## 背景与目标

阶段四主体闭环已经通过审核。本次只修复执行事件、授权密钥生命周期、敏感信息脱敏、多进程消费和模拟器状态纪元，不扩展阶段五能力。

## 方案对比

### 方案一：原模块内零散修补

- 优点：改动少。
- 缺点：密钥、日志、事件和持久化脱敏规则容易不一致，无法形成可验证的安全边界。

### 方案二：集中安全边界与兼容性数据库迁移（采用）

- 新增统一 `SensitiveDataRedactor`，所有持久化、WebSocket、异常和日志出口复用。
- SQLite 增加密钥状态表并为令牌增加 `key_id`，启动时比较稳定指纹并原子撤销旧 `ISSUED` 令牌。
- 执行服务显式发布成功、失败和最终持久化事件。
- 模拟器纪元进入统一车辆状态模型，时间线同时返回历史执行状态与当前模拟器状态。
- 优点：安全语义统一、可测试、兼容现有审计表和哈希链。
- 缺点：需要数据库兼容迁移和更多边界测试。

### 方案三：完整密钥环与外部密钥管理服务

- 优点：支持多密钥并行验证和企业级轮换。
- 缺点：超出阶段四范围，并引入外部凭据和部署依赖。

## 详细设计

### 密钥生命周期

密钥内容不进入数据库。数据库只保存 `key_id`、版本、创建时间、SHA-256 指纹、来源和状态。文件密钥固定为 32 字节；环境变量密钥至少 32 字节。缺失文件仅在安全撤销全部旧 `ISSUED` 令牌后生成；损坏或不可读文件会撤销旧令牌并安全失败。稳定指纹不变时允许未消费令牌跨重启继续验证。

### 脱敏边界

统一脱敏器递归处理敏感字段，并识别当前授权令牌的 base64url 载荷加签名格式。普通文本、复核文本、工作流事件、审计、执行反馈、导出、WebSocket、日志、异常和请求验证错误都在边界处脱敏。签发响应和执行校验函数内部是唯一允许短暂持有原始令牌的位置。

### 执行实时事件

完整复检仍使用原裁决流水线。复检后执行事件严格追加：成功为 `VEHICLE_PRECHECKED → TOKEN_CONSUMED → VEHICLE_EXECUTED → AUDIT_SAVED`；适配器失败将成功事件替换为 `EXECUTION_FAILED`；复检失败为 `VEHICLE_PRECHECKED → AUDIT_SAVED`。持久化工作流事件采用相同语义，所有载荷经过脱敏。

### 状态纪元

模拟器启动生成新纪元，手工重置生成新纪元并累计重置次数。执行历史保存当时的完整状态快照；时间线额外返回当前模拟器状态，使重启后的默认状态不会伪装成历史执行结果。

### 测试策略

将令牌过期、篡改、复用、重启、密钥异常、多进程消费、适配器失败、WebSocket 序列、全库脱敏和状态纪元拆成独立测试。所有测试使用固定临时数据库和固定测试密钥，不修改原78条审计记录。
