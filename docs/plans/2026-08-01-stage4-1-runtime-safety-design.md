# 阶段四点一运行时安全设计

## 背景与目标

阶段四冻结闭环已经具备真实 BGE、HNSW、复核、授权、模拟执行和审计能力。本阶段只修复四类运行时边界：语义模型降级后仍可能放行、内存证据快照无界增长、因果置信度在无样本时产生误导，以及真实验收和源码打包缺少可执行检查。

## 现状与约束

- 冻结基线为 `4cb3dae7c7a96f4b1cf0e78b73dd1181976d3cbb`，75 项测试通过。
- 正常路径必须继续使用 `BAAI/bge-base-zh-v1.5` 与 hnswlib；精确余弦只允许作为索引效率降级。
- Safety Gate、一次性令牌、多进程消费、双哈希链和原 78 条审计正文不可回退。
- 不实现前端、音频、ASR、CARLA、真实 CAN 或阶段五功能。

## 方案对比

### 方案一：仅在响应中标记降级

- 优点：改动小。
- 缺点：授权和执行链仍可能绕过提示，不满足安全边界。

### 方案二：统一能力快照并注入安全关键路径（采用）

- 优点：同一事实驱动安全门、令牌签发、执行前复查、健康、审计和实时事件；BGE 与 HNSW 可独立降级。
- 缺点：需要协调模型、流水线和执行服务的类型兼容。

### 方案三：降级即拒绝启动

- 优点：策略最保守。
- 缺点：失去查询和人工复核能力，不符合 RESTRICTED/QUERY_ONLY 要求。

## 详细设计

### 运行能力与安全裁决

嵌入服务和索引服务提供真实状态，由流水线聚合为 `RuntimeCapabilityStatus`。BGE 降级时，R3 可执行动作由 Safety Gate 直接 BLOCK，R1/R2 可执行动作由决策上限约束为 REVIEW，查询仍返回结果但 `actionable=false`。授权服务拒绝在非 FULL 模式签发；执行服务在原子消费前重新读取能力状态，降级则拒绝并迁移令牌状态。HNSW 单独降级仍保留真实 BGE 向量和正常安全裁决。

### 证据仓库保留

证据以 `evidence_type + source + entity_id` 为稳定流键。动态流使用长度 16 的有界队列，静态规则与权限约束长期保留；本轮节点在处理期间受保护，审计保存后清除 MISSING、冲突派生和解释节点。轮次映射只保留最近 64 轮，历史完整结构继续由 SQLite 审计和工作流记录承载。`current_nodes()` 直接读取每条流最新值和静态节点。

### 因果置信度

后验权重分布的集中程度命名为 `posterior_concentration`；只有样本数达到阈值且至少有两个有效节点时才输出 `decision_confidence`。当前轮始终使用审计保存前的冻结模型版本；审计保存后，仅合格记录累计到 20 条时触发重建，成功后原子替换稳定模型并持久化元数据，失败则保留旧版本。

### 运行预检与安全打包

预检逐项验证指定解释器、BGE 真实推理、768 维归一化、hnswlib 初始化、非降级能力、授权密钥和 SQLite。打包器按固定排除规则遍历 Git 工作树，只输出源文件，且对密钥/数据库路径做二次断言。当前本地授权密钥轮换，但不提交密钥内容。

## 异常与边界处理

- 模型降级不得静默，原因码进入安全门、审计、工作流和 WebSocket。
- 索引降级不伪装成语义模型降级。
- 清理不删除 active turn，且不修改已经写入 SQLite 的审计内容。
- 因果模型重建失败不影响确定性门控和五维评分。
- 旧审计缺失新增字段时使用可空默认值继续解析。

## 测试策略

新增阶段四点一独立测试覆盖能力矩阵、降级裁决与执行、1000 轮有界保留、零样本/单节点/阈值因果置信度、无当前轮泄漏、自动重建失败回退、预检和安全包排除。最后运行 compileall、全量 pytest、真实服务专项验收，并核验原 78 条审计和两条哈希链。
