# 贝叶斯展示诊断旁路设计说明

## 背景与目标

比赛演示需要为主要车控意图展示可复算的贝叶斯风险数值。该数值仅用于解释和展示，不得参与既有 Safety Gate、五维评分、最终裁决、授权或执行。

首批覆盖：关闭前照灯、关闭雨刮器、自动泊车、变道。

## 现状与约束

- 现有主链已经完成语义、证据、硬门、评分、裁决、授权和审计。
- `backend/causal_bayes` 中已有关闭前照灯的 Noisy-OR 原型，但未形成通用展示接口。
- 工作区存在用户未提交修改，实施不得覆盖或混入无关变更。
- 贝叶斯诊断必须位于裁决完成后的只读旁路。

## 方案对比

### 方案一：每个意图独立实现计算器

- 优点：单项实现直接。
- 缺点：重复代码多，难以解释通用性。

### 方案二：通用 Noisy-OR 引擎与意图配置

- 优点：统一公式、统一输出、可按风险机理扩展。
- 缺点：首批配置属于工程专家先验，尚未经过大规模事故数据校准。

### 方案三：复用现有因果置信度作为风险

- 优点：改动最少。
- 缺点：置信度不等于风险，语义错误。

## 推荐方案

采用方案二。诊断接口读取已经保存的轮次语义和证据，在主裁决结束后独立计算；结果只返回给展示层。

## 详细设计

### 架构

新增只读贝叶斯诊断服务和 GET 接口。接口通过既有审计/轮次读取能力获得不可变输入，不调用或修改命令处理流水线。

### 关键组件

- 通用 Noisy-OR 风险聚合器。
- 意图配置注册表：前照灯关闭、雨刮关闭、自动泊车、变道。
- 证据投影器：把标准 EvidenceNode 转换为归一化风险因素。
- 只读 API 响应模型。

### 数据流 / 接口

前端在获得 `turn_id` 后单独调用诊断接口。接口按 occurrence 返回风险概率、安全概率、熵、计算模式、证据输入、因素贡献、缺失证据、模型标识及 `display_only=true`。

### 异常与边界处理

- 已配置意图证据不足时使用显式专家先验，仍返回数值，并标记 `PARTIAL_PRIOR`。
- 未配置意图返回 `supported=false`，不得伪造风险。
- 诊断失败不改变已有轮次或任何裁决字段。

### 测试策略

- 四类意图均返回合法概率，且风险与安全概率之和为 1。
- 危险输入的风险高于对应安全输入。
- 缺失证据返回 `PARTIAL_PRIOR` 和数值。
- 接口只读；调用前后裁决、授权、执行和审计记录不变。

## 风险与待确认项

- 首批概率是可解释的工程先验模型，不宣称完成统计校准。
- 前端布局和视觉样式由后续单独确认，本阶段只交付后端契约。
