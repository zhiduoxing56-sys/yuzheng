# CARLA 当前场景大字号展示设计说明

## 背景与目标

CARLA 模拟页面目前在实时画面下方展示当前激活场景名称、版本号、证据数量和证据类型，但无法直观看出该预设场景实际提交了哪些车辆与环境条件。

本次改动将在 CARLA 实时画面正下方，以较大字号展示已经成功载入的场景名称及其非空配置。展示内容只取自场景预设本身，不使用右侧表格的默认值，也不随尚未提交的下拉框选择变化。

成功标准：

- 载入场景成功后，可以一眼看到当前场景名称和实际配置条件。
- 仅展示场景配置中有值的字段，不出现空字符串、空集合、空对象、`null` 或“未提供”。
- 切换场景下拉框但未点击“载入场景”时，当前场景展示保持不变。
- 一键重置后恢复“当前未载入场景”。
- 桌面端字号醒目，窄屏下内容可以自然换行且不遮挡实时画面。

## 现状与约束

- 页面组件位于 `frontend/src/pages/CarlaPage.tsx`。
- 场景列表接口已经返回 `scenario_id`、`name`、`text` 和用于展示的 `conditions`。
- 当前激活场景接口返回 `scenario_id`，可用于在场景列表中定位真正已经载入的预设。
- `backend/app/services/vehicle/scenario_summary.py` 负责把场景的 `state` 与 `evidence_overrides` 转换为中文条件，但现状会把显式 `None` 渲染成“未提供”，需要收紧空值过滤。
- 现有工作区包含其他未提交改动，本功能实施时必须限制修改范围并避免覆盖无关内容。

## 方案对比

### 方案一：场景名称加大字号条件标签

- 优点：名称醒目、条件便于扫读、字段较多时可自动换行，适合演示页面。
- 缺点：比单行文本多占少量垂直空间。

### 方案二：单段大号摘要文字

- 优点：结构简单、占用空间较少。
- 缺点：条件较多时形成长句，重点不清楚。

### 方案三：键值表格

- 优点：字段和值对齐规整。
- 缺点：与右侧状态表视觉重复，页面更拥挤。

## 推荐方案

采用方案一。实时画面下方先展示大字号“当前场景：场景名称”，再将每一项非空条件显示为独立标签。删除当前区域中的版本号、证据数量和证据类型等技术信息，使该区域只回答“当前载入的场景是什么”。

## 详细设计

### 架构

不新增接口。前端组合现有场景列表和当前激活场景两个数据源；后端只调整场景展示摘要的空值过滤规则。

### 关键组件

- 在 `CarlaPage` 中根据 `activeScenario.scenario_id` 查找对应的 `ScenarioSummary`。
- 当前场景区分为场景标题和条件标签列表。
- 场景名称使用约 `26–32px` 的响应式字号，条件标签使用约 `18–22px` 的响应式字号。
- 条件标签采用弹性换行布局；长内容允许换行，不使用截断省略。

### 数据流

1. 页面加载场景列表及当前激活场景。
2. 用户在下拉框中选择预设，此时只更新待载入的 `scenarioId`。
3. 用户点击“载入场景”，接口成功后重新获取当前激活场景。
4. 使用接口确认的激活场景 ID 匹配场景列表，渲染其名称和 `conditions`。
5. 一键重置后接口返回未激活状态，展示“当前未载入场景”。

### 空值与异常处理

- 场景摘要生成器递归识别无有效展示内容的值：`None`、空字符串、空数组和空对象均视为空。
- 复合条件只保留内部非空字段；整组为空时不生成该条件。
- 前端再对 `conditions` 做一次去空字符串防御性过滤。
- 当前激活场景暂未在场景列表中找到时，仅展示接口提供的场景名称，不伪造条件。
- 场景列表或当前场景请求失败时，维持现有页面可用性，不影响 CARLA 推流与右侧状态操作。

### 测试策略

- 后端单元测试验证状态字段和复合证据中的空值不会生成展示条件。
- 前端组件测试验证成功载入后显示场景名称及所有非空条件。
- 验证下拉框选择变化不会提前改变已激活场景展示。
- 验证未激活和重置状态文案。
- 运行前端 Vitest、TypeScript 检查和生产构建。
- 后端测试必须使用 `D:\software\anaconda\envs\yuzheng311\python.exe`。

## 风险与待确认项

- 场景条件是面向展示的中文摘要，不作为裁决事实源，空值过滤不得修改实际场景加载与证据注入逻辑。
- 当前已确认采用“场景名称 + 大字号条件标签”，且展示对象仅为成功载入的预设场景。
