# 真实数据接入与页面可用性修复设计说明

## 背景与目标

当前前端存在命令即时响应丢失、展示结果等待状态无法收敛、历史浏览覆盖业务当前轮次、固定复核入口无真实轮次、审计响应结构假设过强等基础数据链问题。本轮暂停后续功能、演示控制台、系统维护和视觉设计，仅修改 `frontend`，不修改后端业务代码和冻结契约。

成功标准是：真实接口响应先经过运行时适配；命令提交后立即展示真实提交摘要；持久化展示未及时归档时进入可恢复的部分完成状态；业务当前轮次与历史浏览轮次分离；复核和审计页面按真实状态安全展示；浏览器真实验收全部通过后再执行测试、检查和构建。

## 现状与约束

- 命令输入框硬编码“打开车门”，页面重挂载后造成错误恢复感知。
- 命令提交钩子只保留 `turn_id`，完整即时响应被丢弃。
- presentation 重试窗口过短，失败后提交状态可能停留在等待状态。
- `/review/current` 无真实路由参数，历史证据或复核浏览会覆盖首页当前轮次。
- 审计列表和详情组件直接读取深层字段，缺少运行时适配。
- 响应适配器只兼容契约明确、真实采集确认或测试固定的结构；未知结构必须返回“响应结构异常”。
- 仅保存非敏感浏览器状态。音频对象、原始音频、授权令牌和高级覆盖参数不得写入浏览器存储。
- 本轮禁止新增功能和整体视觉重构。

## 方案对比

### 方案一：集中响应适配器与页面控制器

- 优点：后端变体只在适配层解释，页面依赖稳定展示模型；可精确区分缺失、不可用和结构异常；不增加依赖。
- 缺点：需要系统性调整现有 API、钩子、状态和页面组件。

### 方案二：引入运行时 Schema 库

- 优点：声明式校验完整。
- 缺点：新增依赖并重复维护大量冻结契约类型，迁移范围更大。

### 方案三：组件内兼容读取

- 优点：局部改动快。
- 缺点：组件继续解释后端变体，错误语义分散，无法修复基础数据链。

## 推荐方案

采用方案一。接口层接收 `unknown`，集中适配器校验和归一化为稳定展示模型，专用钩子管理请求与取消，页面控制器协调提交、展示、刷新和路由，页面只组合组件。

## 详细设计

### 运行时响应适配层

新增并集中维护：

- `commandResponseAdapter`
- `turnPresentationAdapter`
- `workflowStatusAdapter`
- `reviewResponseAdapter`
- `auditListAdapter`
- `auditDetailAdapter`
- `auditVerificationAdapter`
- `globalAuditChainAdapter`

适配器接收 `unknown`，检查对象、数组、字符串、布尔值、枚举和必要字段。缺少核心字段返回结构错误；缺少契约允许的可选字段返回明确空值。未知枚举保留原始字符串用于安全显示。未知整体结构不得静默转换成“暂无数据”。组件不得直接解释多个后端结构。

### 真实响应形状采集

使用当前真实后端生成 PASS、REVIEW、BLOCK、音频、复核子轮次、取消和执行记录，检查所有指定接口。只记录字段路径、类型、可空性和结构差异，不记录授权令牌或完整敏感响应，输出 `frontend/docs/plans/real-response-shape-audit.md`。当前 TypeScript 类型逐项与真实响应对比，差异只在前端类型和适配器中修正，不伪造后端字段。

### 会话状态与安全迁移

`currentTurnId` 重构为 `activeTurnId`。业务当前轮次只由新命令成功、复核子轮次成功或首页显式选择更新；证据、复核和审计路由中的 `viewTurnId` 不更新它。

会话存储键增加版本号。启动时对旧版当前轮次和最近轮次执行一次性、类型校验后的安全迁移；迁移仅搬运有效轮次编号，不生成默认指令或虚构摘要，完成后删除旧键。

草稿使用 `sessionStorage` 键 `yuzheng.v2.commandDraft.<sessionId>`，只保存文本、发声位置和说话人角色。最近提交摘要使用 `yuzheng.v2.lastSubmission.<sessionId>`，保存真实提交文本或真实转写、来源、输入方式、`turnId` 和提交时间。新建会话删除旧会话草稿和当前提交摘要。关闭标签页后无需长期恢复。

### 命令提交与展示状态机

状态为：`idle → validating → submitting → processing → waiting_presentation → completed | partial | failed`。

命令接口成功后保存完整非敏感适配结果，立即更新 `activeTurnId` 和“本轮提交指令”摘要，再清除草稿。文本摘要优先使用用户原始输入；音频和麦克风摘要优先使用真实转写并标注来源。即时结果与最终持久化结果分区标识。

新轮次 presentation 使用约 18 秒有限递增重试。达到上限进入 `partial`，保留新轮次摘要和上一轮完整结果，解除输入禁用并提供“重新获取最终结果”；该操作只重新读取 presentation，不重复提交。presentation 结构错误或请求错误必须通知提交状态机并保证输入可继续使用。

### 页面加载和空状态语义

主数据未返回前只渲染统一加载区域。区域级状态明确区分：正在加载、已加载、本轮不适用、后端未提供、尚未归档、请求失败、数据结构异常。禁止统一显示“暂无”。

### 复核入口与写权限

删除 `/review/current` 路由。顶部“复核授权”只在存在 `activeTurnId` 时链接 `/review/{activeTurnId}`，否则禁用。复核页面的 `viewTurnId` 来自地址且不覆盖 `activeTurnId`。

复核写操作同时依赖：当前查看轮次等于最新可写业务轮次、工作流状态允许、后端 review 信息允许。历史父轮次、PASS、BLOCK、CANCEL 和已执行轮次只读展示；只有真实可写 REVIEW 轮次显示写操作。复核生成子轮次后更新 `activeTurnId`。

### 审计链与审计兼容

全局链适配器只处理真实采集或测试固定的结构。若为 auditId 到布尔值字典，全部为真才通过，存在假值显示异常数量，空字典显示后端没有可校验记录；其他未知结构显示响应结构异常。

审计列表适配成 `auditId`、`turnId`、`createdAt`、`instructionSummary`、`action`、`target`、`riskLevel`、`finalDecision` 和 `executionStatus`。普通、复核子轮次、CANCEL、已执行记录都必须安全显示。详情先适配为区域展示模型，单一区域缺失不使整页崩溃。

审计编号只有在适配器确认是有效非空字符串时才生成详情链接。尚未归档只显示说明和“刷新当前轮次”，不得生成空编号、`undefined`、`null` 或空地址。

## 数据流与依赖

`API unknown → 响应适配器 → 专用数据钩子 → 页面控制器 → 展示组件`。

适配器只依赖基础校验工具与展示类型；专用钩子只依赖 API 和适配器；专用钩子之间不互相导入；控制器协调刷新版本和回调；页面只组合组件，不存在循环依赖。

## 异常与边界处理

- 接口失败保留已成功数据并提供重试。
- 新提交保留上一轮完整结果并明确标识。
- 任意读取失败不得永久锁住输入。
- 页面离开、新会话或新指令开始时取消旧读取。
- 手动重试 presentation 不重复写请求。
- 原始和脱敏敏感响应均不写控制台或仓库。

## 测试与验收

先完成真实响应采集和适配器测试，再逐项执行附件列出的浏览器真实验收，包括命令摘要、三条不同指令、partial、真实复核入口、PASS/REVIEW/BLOCK、历史浏览不覆盖 activeTurnId、审计链结构、审计记录变体、缺失 auditId、重试和控制台无未捕获异常。

浏览器真实验收完成后才运行：

```powershell
npm.cmd run test
npm.cmd run lint
npm.cmd run build
```

构建通过不能替代真实页面验收。完成后停止，不进入任何新功能或视觉重构。
