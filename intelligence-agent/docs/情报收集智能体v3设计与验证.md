# 情报收集智能体 v3 —— 受控安全知识发现智能体

生成时间：2026-08-15

## 一、定位（动态安全知识闭环）

```
                    ┌────静态安全知识────┐
法规/标准 ─────────→│   Trusted KB       │
                    └────────┬───────────┘
                             ↓
                    Evidence → CBN 裁决
                             ↑
                    人工审核/版本冻结
                             ↑
事故/召回 → 情报智能体 v3 → Candidate KB（候选风险知识）
```

- **上一阶段已解决**：Trusted KB 内部可靠性（MMR=0、Frozen Test 独立评测、Query Builder v2、Novelty 循环论证修复）
- **本阶段解决**：Trusted KB 外部如何持续发现新风险，并在不污染正式裁决链的前提下转化为可审核知识

## 二、术语体系（严格区分）

| 概念 | 含义 | 例 |
|---|---|---|
| Physical Evidence | 实时车辆物理信息 | VEHICLE_SPEED=60km/h |
| Trusted Knowledge Node | 审核后的正式安全知识（L1-L2） | 法规条款节点 |
| Candidate Risk Node | 事故产生的候选风险知识（L5/PENDING） | "尾灯间歇失效风险" |
| Incident Record | 原始事故/召回记录（不可变快照） | NHTSA 召回条目 |

## 三、9 层架构

| 层 | 模块 | 职责 | 关键设计 |
|---|---|---|---|
| 1 | source_layer.py | 白名单源采集 | RawIncidentRecord 不可变快照 + content_hash + parser_version + 来源权威等级 |
| 2 | clusterer.py | Normalize + Dedup/Cluster | **IncidentCluster 基本单元**：同事故多源聚合，corroboration 增信；先聚合后生成节点（防同事故多节点） |
| 3 | analyzer.py | 结构化分析 | Component(family,sub) 最长前缀匹配；FailureMode/OperatingCondition/Consequence 枚举提取；Severity 分级（触发句可追溯） |
| 4 | mapping_v2.py | **Mapping v2 三路融合** | M_ontology ∪ M_retrieval ∪ M_incident；**域守卫**；**ABSTAIN/UNMAPPED** 机制（本体缺口即知识发现） |
| 5 | novelty_engine.py | Novelty v2 | 结构重叠三维度（域覆盖+证据重叠+嵌入相似），独立于 Mapping（无循环论证） |
| 6 | prioritizer.py | 审核优先级 | **P0/P1/P2 仅排序审核**，绝不参与安全裁决（与 CBN SafetyScore 彻底分离） |
| 7 | node_builder.py | Candidate Node Builder | KnowledgeNode v2 Schema / L5 / PENDING_REVIEW，全部字段可追溯 |
| 8 | integrator.py(ReviewBoard) | Human Review | REJECT / MERGE / PROMOTE，决策留痕（reviewer/时间/理由/快照） |
| 9 | integrator.py(TrustedIntegrator) | Trusted Integration | **Conflict Check**（CLEAR/OVERLAP/CONFLICT/NEW_INTENT）→ 版本化晋级 → 重建 HNSW 信号 |

### Mapping v2 三路融合（防循环论证）

```
M_final = M_ontology ∪ M_retrieval ∪ M_incident
  M_ontology ：Component → CapabilityDomain → CandidateIntentSet（固定本体，不依赖 KB）
  M_retrieval：Trusted KB HNSW（仅增强，阈值 0.68）
  M_incident ：FailureMode/Consequence → 意图（事故自身结构）
  域守卫      ：非安全域意图必须与事故能力域匹配；安全域（SEC_*/DATA_*/OTA_*）仅对电子/软件类部件放行
  ABSTAIN     ：三路无候选 → UNMAPPED + "现有语义本体存在覆盖缺口"（这是知识发现结果）
```

### 集成测试中修复的关键缺陷（过程记录）

1. **Mapping 兜底错误**：无意图组件曾兜底 BRAKE → 改为 ABSTAIN（不强行分配）
2. **组件前缀匹配缺陷**："FORWARD COLLISION AVOIDANCE"/"SERVICE BRAKES, HYDRAULIC"/"LATCHES/LOCKS/LINKAGES" 精确匹配失败 → 最长前缀匹配
3. **域守卫缺失**：安全带召回因"碰撞后果"被误映射 EMERGENCY_BRAKE → 域守卫拦截
4. **安全域跨域过宽**：机油泄漏→SEC_INCIDENT_RESPONSE → 部件电子性守卫（仅电子/软件类允许跨安全域）
5. **优先级口径**：f_voice 改用 mapping 结果（MAPPED+intents），不再用 raw ontology_intents
